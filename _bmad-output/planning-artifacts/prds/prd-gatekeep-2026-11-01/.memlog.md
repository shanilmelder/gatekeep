- (event) PRD started before the brief was finished; inputs are design-prompt.md, SCREENS.md, the three exports, and the brief run's memlog and research digest.
- (assumption) Carried from the brief run: self-hosted platform for the user's own production projects, also a learning exercise, expected 80+ stories, heavy security requirements.
- (decision) No specific Keycloak or Clerk failure drives this; the user is building it because they want to, so the PRD must not claim a feature gap.
- (decision) User chose the fast path: batch remaining gaps, then draft the full PRD with ASSUMPTION tags.
- (decision) User corrected the default: v1 must support multiple isolated tenants, so tenant isolation is a v1 requirement. User raised no other objection, so the remaining fast-path defaults stand as assumptions.
- (event) Fast-path draft written: 44 FRs, 19 NFRs, 12 assumptions and 6 open questions, with tenants in v1 and the section cut in section 7; status stays draft until user review and Finalize.
- (decision) Tenants are addressed by subdomain of the Deployment's domain, so cookies and passkeys are bound to the exact Tenant subdomain.
- (decision) Hosting target is an on-premises server, so the Deployment needs no cloud-managed services; availability target A-6 now depends on server redundancy.
- (decision) Security gate is a self-assessment against OWASP ASVS, not a paid penetration test; the user accepted this after being advised an external test was preferable.
- (decision) Quickstarts are React, Next.js, Node, .NET and Python.
- (assumption) User's answers to the review questions were taken as approval to run finalization, with a rubric and a security reviewer selected.
- (event) All four checks returned: rubric 32 findings, 3 critical; security 37 findings, 4 critical; both reconciliations found gaps. Verdict is not ready to finalize; awaiting user decisions on Admin identity, passkey and MFA rules, key custody and server redundancy.
- (decision) Admin identity: Deployment-level Owner, separate Admin sign-in using passkey or security key only with no email recovery, one Admin account can hold roles across Tenants, backup key or recovery codes required, first Admin needs a one-time server token.
- (decision) Passkeys and MFA: a user-verified passkey satisfies MFA, anyone with a passkey or Factor gets recovery codes, password reset does not sign in under Always, email codes never count as a second factor, first Factor enrolment needs a verified email.
- (decision) Key custody: master key stored offline and separate from backups, restore rehearsed with it; losing both means Users re-enrol and all keys are replaced.
- (decision) Server: assume internet-reachable with no redundancy, availability target 99.5 percent, Admin Dashboard reachable only by VPN or private network.
- (decision) Keep v1 scope and restate the promise as the smallest product that is safe with multiple tenants.
- (change) PRD revised from all four checks: 50 FRs, 21 NFRs, security limits table, permission matrix, UJ-6, design-change list and build sequence; deferred items assigned releases; open questions reduced to three non-blockers; self-assessment recorded as an accepted risk.
