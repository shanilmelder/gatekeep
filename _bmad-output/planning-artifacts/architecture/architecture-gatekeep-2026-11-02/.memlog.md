- (decision) CHALLENGE KMS: cloud KMS conflicts with FR-1. Replaced with self-hosted OpenBao Transit, non-exportable per-Tenant keys. Barrier unseal key = PRD Master Key; snapshot without it reveals nothing (FR-4). Rejected in-process keys: internet-facing RCE could copy private keys (Storm-0558 precedent in research).
- (assumption) Unattended restart: OpenBao static seal with key held via systemd-creds sealed to TPM2, plus offline escrow. Static seal docs warn it needs an existing root of trust; the TPM is that root. If host has no TPM, root-only file on a separate volume, weaker; Operator confirms hardware.
- (decision) CHALLENGE Redis: removed from v1. Single host process needs no shared cache, Redis has no RLS so FR-8 keying would depend on app discipline, and it adds a store to back up, patch and secure. Sessions in Postgres; counters in UNLOGGED tables under RLS; IRateLimiter port lets Valkey 9 slot in if scale-out arrives.
- (decision) CHALLENGE queue: no broker. Postgres jobs table written in the same transaction, FOR UPDATE SKIP LOCKED, LISTEN/NOTIFY wake. MassTransit 9 is commercial; Hangfire and Wolverine do not enforce the FR-8 explicit-Tenant rule; RabbitMQ adds a failure domain with no benefit.
- (decision) CHALLENGE React for Hosted Login: keep React but the server embeds the current step as JSON in the first HTML so cards arrive complete with no fetch; theme is a server-generated same-origin stylesheet so no flash. Requires JS; overturns EXPERIENCE [ASSUMPTION] 'Password and code forms work with JS off'. Rejected Razor (second component system) and Node SSR (new runtime in the auth path).
- (decision) CHALLENGE RLS alone: keep shared-schema RLS (rejected DB-per-tenant: runtime DDL, per-tenant pools, partial-failure upgrades break FR-3) but harden: FORCE RLS, restrictive policy, non-owner roles, per-host DB roles, composite FKs, CI catalogue check, cast fails loudly when unscoped.
